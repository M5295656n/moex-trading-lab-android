# Инкрементальная синхронизация и контроль качества истории

## Загрузка истории

Экран «История свечей» позволяет выбрать инструмент из локального каталога, таймфрейм (1, 10, 60 минут или день) и начальную дату.

- `syncInstrumentHistoryIncrementally` получает максимальное время `begin` для пары инструмент + таймфрейм из Room.
- Если история уже есть, запрос MOEX ISS начинается с последней сохранённой свечи включительно.
- Если истории нет, используется указанная начальная дата; пустое значение оставляет диапазон на усмотрение ISS.
- Повторная загрузка граничной свечи намеренная: биржа может уточнить ещё формирующуюся свечу.
- Составной первичный ключ Room заменяет запись той же свечи, поэтому повтор не создаёт дубль.
- При повторе timestamp на более поздней странице значение свечи заменяется более поздним ответом ISS.
- Ошибка сети не приводит к сохранению нового coverage как успешной загрузки.

Ограничение одного запуска: 200 страниц по 500 строк (до 100 000 свечей). `PAGE_LIMIT_REACHED` и `PAGINATION_STALLED` явно отображаются как неполная загрузка. `COMPLETE` означает только то, что ISS вернул короткую завершающую страницу в рамках запрошенного диапазона; это не доказывает доступность всей истории инструмента с момента листинга.

## Состояние покрытия

Для каждой пары инструмент + таймфрейм в `history_coverage` сохраняются источник, endpoint, запрошенный диапазон, фактические первая и последняя свечи, время получения, число страниц, размер страницы, статус пагинации, число пропущенных строк, статус проверки пропусков и актуальность.

Повторная дозагрузка не удаляет ранее накопленную историю. Отсутствующие значения OHLC и объёма остаются `NULL`, не заменяются нулями.

## Проверка качества свечей

`CandleQualityAnalyzer` проверяет отсутствующие OHLC значения, внутреннюю согласованность OHLC и отрицательный объём. Результат содержит количество свечей и счётчики замечаний. Проверка не исправляет и не подменяет исходные биржевые значения.

## Ограничение gap detection

Автоматическое определение пропусков по простому интервалу времени намеренно не включено. Торговые сессии, аукционы, вечерние/утренние периоды, выходные и праздники различаются по рынкам и таймфреймам. Без проверенного календаря такой алгоритм пометил бы нормальные паузы как пропуски. Поэтому `gapCount` остаётся `NULL`, пока не появится календарно-осведомлённый валидатор.

## Изменения схемы Room

Для пользовательской загрузки истории используются уже существующие таблицы `candles` и `history_coverage`, а также существующие DAO-запросы. Новая миграция Room не требуется.
