# Локальная история SecuritiesListing

## Назначение

Компонент сохраняет бесплатные публичные снимки MOEX SecuritiesListing, чтобы со временем видеть изменения допуска российских акций к дополнительным торговым сессиям. Это отдельная справочная история. Она не является календарём торгов, не доказывает наличие сделок и не участвует в расчёте полноты свечей или backtesting.

Источник:
- ZIP: `https://iss.moex.com/file/stock_boardsecid/SL.ZIP`
- Внутри ZIP ожидается один DBF-файл.
- Токен и платная подписка не используются.
- В Android используется обычная HTTPS-проверка сертификата. TLS-проверка не отключается.

## Объём и область хранения

Исходный DBF содержит порядка 148 тыс. строк по большому числу инструментов и режимов торгов. Не сохраняем весь файл в Room каждый день.

После проверки DBF оставляем только строки, у которых одновременно совпали `SECID + BOARDID` с локальным каталогом акций (`market_instruments.market = SHARES`). Фьючерсы и индексы в этот снимок не входят: URL относится к справочнику фондового рынка.

Поэтому:
- в заголовке сохраняются общее число исходных/активных записей и число строк, отобранных для локального каталога;
- исключённые строки не сохраняются;
- если каталог акций ещё не загружен, загрузка снимка не выполняется;
- если позже пользователь добавит инструмент в каталог, прошлые снимки автоматически не восстанавливаются.

## Разбор DBF

Парсер:
1. Проверяет ZIP-сигнатуру и наличие ровно одного DBF.
2. Проверяет размеры заголовка, записи, число записей и границы файла.
3. Ищет обязательные поля по именам, а не по фиксированным позициям.
4. Проверяет тип и ширину обязательных полей:
   - `TRADEDATE` и `TRDSESDATE` — DBF Date, 8 байт;
   - `BOARDID`, `SECURITYID` — символьные поля;
   - `MORNINGSES`, `EVENINGSES`, `WEEKENDSES` — символьные поля шириной 1.
5. Не требует точного количества полей: дополнительные неизвестные поля допустимы.
6. Читает идентификаторы/флаги как ASCII. Русские подписи не нужны для бизнес-ключей; CP866 подтверждён для контрольных текстовых полей в наблюдаемом файле, но парсер не зависит от их декодирования.
7. Для флагов `Y` означает true, `N` — false; любое другое значение сохраняется как null и увеличивает `unknownFlagCount`. Неизвестное не превращается в N.
8. Одинаковые дубликаты ключа учитываются отдельно и не создают повторную запись; конфликтующие дубликаты отвергают весь снимок.
9. Требует одну дату `TRADEDATE` на весь файл. `TRDSESDATE` хранится отдельно в каждой строке.

Ключ строки: `snapshotId + TRADEDATE + TRDSESDATE + BOARDID + SECURITYID`.

## Room

Версия базы увеличена с 3 до 4, добавлена аддитивная миграция `MIGRATION_3_4`. Старые таблицы и данные не переписываются.

- `securities_listing_snapshots` — заголовок снимка: SHA-256, URL, имя DBF внутри ZIP, дата торгов, время получения, число записей, фильтрация, дубликаты, неизвестные флаги и статус.
- `securities_listing_entries` — выбранные пары SECID/BOARDID и три nullable-флага; внешний ключ с каскадным удалением при удалении заголовка.
- Записи вставляются порциями по 500 внутри транзакции.
- SHA-256 исходного ZIP используется как `snapshotId`: повторная загрузка идентичного файла обновит тот же снимок, а изменившийся файл сохранит отдельную версию.

При ошибке HTTP, некорректном ZIP/DBF, конфликтующих дубликатах или неполной структуре Room не изменяется; предыдущий успешный снимок остаётся доступен.

## Статусы

- `COMPLETE` — все сохранённые флаги имеют известные значения, конфликтов и дубликатов нет.
- `COMPLETE_WITH_DUPLICATES` — найдены идентичные дублирующиеся строки.
- `PARTIAL_FLAGS` — хотя бы один флаг в исходном DBF неизвестен.
- `NO_LOCAL_MATCHES` — файл разобран, но пары локального каталога не найдены.

Статус относится к качеству снимка справочника, а не к полноте торговой истории.

## Интерфейс и дальнейшая автоматизация

На вкладке «Данные» добавлена ручная команда «Загрузить текущий снимок» и просмотр метаданных последнего успешного снимка. Автоматическое фоновое расписание пока не включено: следующий этап — проверка безопасного ежедневного запуска при открытии приложения, с явной фиксацией пропущенных дней и без WorkManager/платных сервисов.

До этого момента снимки накапливаются только после ручного запуска пользователем. Не утверждать, что история ежедневная или непрерывная, если в Room нет соответствующей даты.

## Жёсткие ограничения

- Не подключать эти данные к `CandleGapAnalyzer`, `BacktestHistoryGate` или `MoexDailyHistoryCoverageVerifier`.
- Не выводить ожидаемые свечи из флагов допуска.
- Не считать `Y` подтверждением фактической сделки.
- Не восстанавливать пропущенные даты из текущего файла.
- Не обходить TLS, не добавлять токены, секреты или платные API.
