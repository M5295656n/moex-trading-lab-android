# Постоянная подпись APK — MOEX Trading Lab

## Назначение

Для всех устанавливаемых сборок MOEX Trading Lab используется один отдельный постоянный Android signing key. Он не связан с MyCapital и не должен заменяться после первой установки приложения.

- applicationId: `ru.moex.tradinglab`
- Начальная версия: `1.0.0` / `versionCode=1`
- Одинаковый сертификат применяется к Debug и Release APK.
- При каждом следующем выпуске `versionCode` увеличивается; `applicationId` и ключ не меняются.
- Файл JKS и пароли запрещено коммитить в Git.

## Настройка GitHub Actions

В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте пять секретов из индивидуального защищённого пакета ключа:

1. `MOEX_SIGNING_KEYSTORE_BASE64` — Base64 всего файла JKS одной строкой.
2. `MOEX_SIGNING_STORE_PASSWORD` — пароль хранилища.
3. `MOEX_SIGNING_KEY_ALIAS` — alias ключа.
4. `MOEX_SIGNING_KEY_PASSWORD` — пароль ключа.
5. `MOEX_SIGNING_CERT_SHA256` — SHA-256 сертификата без двоеточий.

Не публикуйте значения секретов в Issues, PR, коммитах или логах. Сохраните резервную копию JKS отдельно от Git.

## Поведение CI

- Пока все пять секретов не настроены, CI публикует только диагностический Debug APK. Его нельзя устанавливать как пользовательскую версию или использовать для обновления.
- После настройки всех секретов CI собирает Debug и Release APK одним ключом, проверяет подпись и ожидаемый SHA-256 сертификата, package name и начальную версию.
- Только APK с постоянным сертификатом предназначены для установки и последующих обновлений.
- Необходимо сохранить JKS: потеря ключа означает невозможность выпускать совместимые обновления для уже установленной версии.

## Первичная установка и обновления

Если на устройстве уже установлена сборка с другим сертификатом, Android не позволит обновить её поверх. Перед первой установкой APK с новым постоянным ключом удалите старую установку (пользователь подтвердил отсутствие локальных данных). После этого все сборки с тем же ключом и более высоким `versionCode` устанавливаются поверх.

## Выпуск новых версий

Для каждого выпуска увеличивать `versionCode` строго выше предыдущего и обновлять `versionName` по последовательной схеме. Не менять `applicationId` и signing key. До передачи APK проверить CI, подпись, SHA-256, package name, versionCode/versionName и наличие артефакта.
