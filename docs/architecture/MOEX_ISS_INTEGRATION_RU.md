# Интеграция MOEX ISS — этап 2

## Статус

Реализуется read-only транспортный слой. Он предназначен для запросов к публичному HTTP API ISS и не содержит брокерских операций.

## Базовые принципы

- Базовый адрес: `https://iss.moex.com/iss/`.
- Формат ответа: JSON; метаданные ISS отключаются параметром `iss.meta=off`.
- Табличный ответ разбирается по массивам `columns` и `data`; соответствие значений колонкам проверяется для каждой строки.
- Пустые значения остаются null и не преобразуются в нули.
- В модели ответа сохраняется endpoint и время получения.
- HTTP-ошибки и некорректный JSON возвращаются как явные ошибки.
- Клиент выполняет сетевой вызов на IO dispatcher и использует ограниченные тайм-ауты.
- Клиент только читает данные; методов отправки заявок нет.

## Первые проверяемые направления API

| Назначение | ISS endpoint | Статус |
|---|---|---|
| Акции, каталог | `engines/stock/markets/shares/securities.json` | Требуется проверка реального ответа |
| Фьючерсы, каталог | `engines/futures/markets/forts/securities.json` | Требуется проверка реального ответа |
| Опционы (не входят в первую очередь) | `engines/futures/markets/options/securities.json` | Справочный endpoint |
| Свечи | `engines/{engine}/markets/{market}/securities/{SECID}/candles.json` | Требуется проверка параметров интервала и пагинации |
| Метаданные endpoint | суффикс `/columns.json` | Использовать для проверки схемы таблиц |

## Ограничения доступа и лицензирование

Публичная документация MOEX указывает, что анонимный доступ к рыночным данным может быть задержанным; real-time доступ предоставляется по подписке. Доступность исторических данных зависит от типа данных и прав доступа. Исторические данные в namespace `/iss/history` могут иметь отдельные ограничения; в документации MOEX отдельно оговорено, что исторические данные (кроме индексов) доступны подписчикам.

MOEX также публикует условия использования информации ISS. До распространения приложения, предоставления данных третьим лицам или использования данных в коммерческом продукте необходимо отдельно проверить и при необходимости оформить соответствующие права. Техническая доступность endpoint не означает наличие лицензии.

## Следующая проверка

1. Проверить фактические JSON-ответы каталогов акций, фьючерсов и индексов.
2. Зафиксировать реальные схемы колонок и фильтры по board/market.
3. Проверить пагинацию и максимальный размер страницы.
4. Проверить свечи на нескольких SECID, рынках и интервалах, включая пустые диапазоны.
5. Сопоставить фактическую глубину истории с торговым календарём и доступом.
6. Только после этого строить репозитории и схему хранения свечей в Room.
