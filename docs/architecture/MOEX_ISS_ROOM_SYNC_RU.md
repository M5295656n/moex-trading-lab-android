# Синхронизация MOEX ISS → Room

## Назначение

`MoexMarketDataSync` — orchestration layer между read-only `MoexIssDataRepository` и локальным `MarketDataStorage`. Он не содержит брокерских API и не отправляет торговые заявки.

## Каталоги

`syncCatalog(market)` загружает каталог указанного рынка и сохраняет инструменты в `market_instruments`. При дедупликации учитывается комбинация `market + boardId + SECID`: одна ценная бумага может присутствовать в нескольких режимах торгов, и эти записи нельзя схлопывать только по SECID.

## История инструмента

`syncInstrumentHistory(instrument, intervalMinutes, from, till)`:

1. Проверяет поддерживаемый интервал и диапазон параметров.
2. Сохраняет инструмент до записи свечей, чтобы выполнить внешний ключ Room.
3. Формирует market-specific endpoint `.../securities/{SECID}/candles`.
4. Запрашивает страницы ISS с параметрами `interval`, `from`, `till`, `start`, `limit`.
5. Записывает свечи и метаданные покрытия одной Room-транзакцией.

Текущие интервалы синхронизации: 1, 10, 60 минут и дневной интервал ISS (24). Это начальный набор для проверки связки; расширение списка должно сопровождаться проверкой доступности каждого рынка/инструмента.

## Сохранение качества данных

- Отсутствующие OHLCV остаются NULL.
- Существующие свечи обновляются по составному ключу инструмента, интервала и времени.
- Ошибка сетевого запроса не помечает историю как успешно синхронизированную.
- `COMPLETE` означает завершение пагинации ISS, а не отсутствие временных разрывов.
- Проверка gap-free истории и оценка свежести остаются отдельными следующими задачами.

## Ограничения текущего этапа

- Нет автоматического фонового расписания синхронизации.
- Нет UI-индикатора статуса загрузки и качества истории.
- Нет инкрементальной стратегии дозагрузки только новых/недостающих диапазонов: текущий запрос получает диапазон, заданный вызывающим слоем.
- Набор интервалов и endpoint'ов требует отдельного smoke-тестирования на каждом рынке.
