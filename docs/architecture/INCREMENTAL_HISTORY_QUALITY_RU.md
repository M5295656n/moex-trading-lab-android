# Инкрементальная синхронизация и контроль качества истории

## Инкрементальная дозагрузка

`syncInstrumentHistoryIncrementally` получает максимальное время `begin` для пары инструмент + таймфрейм из Room.
- Если история уже есть, запрос MOEX ISS начинается с последней сохранённой свечи включительно.
- Если истории нет, используется `initialFrom`; при `null` сохраняется поведение ISS по умолчанию.
- Повторная загрузка граничной свечи намеренная: биржа может уточнить ещё формирующуюся свечу.
- Составной первичный ключ Room заменяет запись той же свечи, поэтому повтор не создаёт дубль.
- Ошибка сети не приводит к сохранению нового coverage как успешной загрузки.

Дозагрузка не удаляет ранее накопленную историю и не пересчитывает диапазоны задним числом.

## Проверка качества свечей

`CandleQualityAnalyzer` проверяет отсутствующие OHLC значения, внутреннюю согласованность OHLC и отрицательный объём. Результат содержит количество свечей и счётчики замечаний. Проверка не исправляет и не подменяет исходные биржевые значения.

## Ограничение gap detection

Автоматическое определение пропусков по простому интервалу времени намеренно не включено. Торговые сессии, аукционы, вечерние/утренние периоды, выходные и праздники различаются по рынкам и таймфреймам. Без проверенного календаря такой алгоритм пометил бы нормальные паузы как пропуски. Поэтому `gapCount` остаётся NULL, пока не появится календарно-осведомлённый валидатор.

## Без миграции Room

Добавлены только DAO-запрос максимального `begin` и функции анализа в Kotlin. Схема БД не меняется; миграция не требуется.
