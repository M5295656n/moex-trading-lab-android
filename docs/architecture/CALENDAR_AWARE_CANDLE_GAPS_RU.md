# Календарно-осведомлённая проверка свечей

## Уже реализованная основа

В проекте уже существует контракт ExpectedCandleSchedule и компонент CandleGapAnalyzer в пакете data.sync. Анализатор:

- считает пропуском только timestamp, присутствующий в ожидаемом расписании;
- отдельно показывает неожиданные timestamp;
- не учитывает дубликаты как отдельные свечи;
- возвращает UNKNOWN (gapCount = null), если расписание или границы диапазона отсутствуют.

Повторная реализация алгоритма не нужна. Следующий этап — подключить достоверный источник ожидаемого расписания к существующему контракту.

## Проверенные ограничения источников

- Engine timetable/dailytable описывает работу движка, но не расписание торгов конкретной бумаги или контракта. Его нельзя использовать как генератор ожидаемых свечей.
- Публичные URL ISS calendars/off_days и calendars/session при live-проверке возвращали HTML, а не машинно-читаемую таблицу ISS.
- Документированные ALGOPACK calendar endpoints доступны через APIM и без токена отвечают 401. Пользователь подтвердил, что ключа ALGOPACK у него нет.
- Архив SecuritiesListing содержит справочник инструментов и досок на дату выгрузки; сам по себе он не является календарём сессий.
- Официальное сообщение MOEX от 20.01.2021 указывает, что DBF-публикация SecuritiesListing прекращалась с 01.02.2022, а доступ к новым выгрузкам ISS SecuritiesListing становился авторизованным с 20.02.2021. Поэтому старый `SL.ZIP` нельзя использовать как актуальный бесплатный источник торговых дат.
- 23.11.2026 был фактически скачан и проверен `SL.ZIP` по адресу `https://iss.moex.com/file/stock_boardsecid/SL.ZIP`: HTTP 200, 1 795 921 байт, ZIP integrity OK. Внутри находился `SL231126.dbf` с 148 519 строками справочника (5 241 SECURITYID, 186 BOARDID, 0 дубликатов ключей). Это подтверждённый архив справочника, не свечей.

Исторические свечи приложение получает отдельными запросами к MOEX ISS candles endpoint с пагинацией. В сохранённой истории и доступных файлах проекта не найден отдельный ZIP со свечами; не следует путать свечной endpoint и архив справочника SecuritiesListing.

## Решение без ключа ALGOPACK

На текущем этапе не подключать SecuritiesListing как календарный источник: его актуальная выгрузка требует авторизации, а старый DBF-архив устарел. Не использовать набор фактически полученных свечей в качестве ожидаемого расписания — это скроет отсутствующие свечи и создаст круговую проверку.

Для дневных свечей продолжать получать реальные бары напрямую из MOEX ISS. Отдельный статус полноты дневной истории можно будет рассчитывать только после подтверждения доступного независимого источника торговых дат или иного официального календаря, полного на весь диапазон и согласованного с рынком/board/SECID.

Для внутридневных свечей gap detection и calendar-based freshness остаются UNKNOWN до получения проверенного расписания сессий. Engine timetable не использовать как замену.

Публичный торговый календарь MOEX (`https://www.moex.com/ru/tradingcalendar`) и официальные PDF-календари по годам являются дополнительными кандидатами для исследования дневных торговых дат. Они учитывают специальные выходные и праздничные сессии, поэтому правило «понедельник–пятница» недопустимо. Однако найденная публичная страница не подтверждает стабильный машинно-читаемый исторический интерфейс для приложения, а доступный PDF-календарь 2026 года сам по себе не закрывает весь исторический диапазон. До проверки архива календарей по годам, формата и соответствия конкретному рынку/board этот источник не подключается в production.

Официальное руководство ISS отдельно предупреждает, что пространство `/iss/history` для исторических результатов торгов (кроме индексов) доступно подписчикам. Это ограничение нельзя автоматически переносить на уже используемый приложением namespace `/iss/.../candles`, но оно исключает предположение, что любой исторический endpoint MOEX бесплатен и анонимен.


## Уточнение по официальному машинно-читаемому календарю MOEX

Официальное описание API подтверждает, что `off_days` содержит календарные торговые/неторговые даты для фондового, валютного и срочного рынков, а `session_schedule` — периоды с `tradedate`, `tradingsession`, `boardid`, `secid`, `type`, `time_from`, `time_till`. Для акций и фьючерсов это существенно лучше engine timetable и соответствует нужному уровню детализации.

Однако с 01.01.2026 доступ к сервису «Машиночитаемый календарь» тарифицируется отдельно: для индивидуального использования без распространения — 20 000 ₽/мес. за один рынок или 50 000 ₽/мес. за пакет трёх рынков; для демонстрации в приложении — 22 000 ₽/мес. за один рынок или 55 000 ₽/мес. за пакет. Поэтому считать эти JSON endpoints бесплатным публичным источником нельзя. Без оформленного доступа/токена их не подключать.

Публичная веб-страница MOEX Trading Calendar остаётся доступной для просмотра человеком и содержит специальные выходные/дополнительные сессии. Она полезна для ручной сверки, но пока не подтверждена как стабильный и лицензированно пригодный для автоматической загрузки API для всего исторического диапазона приложения.

## Уточнение по ZIP-архивам

В описании машинно-читаемого календаря действительно упоминаются ZIP-файлы, но это архивы исключений/приостановок торгов по инструментам и режимам (например, `suspended_details.csv.zip` и `session_suspended_YYYY-MM-DD.csv.zip`), а не OHLCV-свечи. Их нельзя использовать вместо свечной истории.

В документации ISS объект `/candles` относится к предварительно рассчитанным свечам, а объект `/archives` не документирован как архив свечей; документированные исторические архивы относятся к данным `securities` и `trades`. Отдельный ZIP-файл со свечами для этого проекта в текущих материалах не идентифицирован. До обнаружения конкретного файла, URL и содержимого не считать, что такой архив уже был загружен.

Публичный namespace `/iss` предоставляет рыночные данные с задержкой, тогда как namespace `/iss/history` для исторических результатов торгов (кроме индексов) требует подписки согласно руководству MOEX. Это не отменяет уже проверенную доступность используемого свечного endpoint `/iss/.../candles`, но запрещает смешивать свечи, архивы итогов торгов и архивы сделок.

## Требования к адаптеру расписания

1. Учитывать рынок, SECID, BOARDID и таймфрейм.
2. Формировать отдельные ожидаемые timestamp внутри каждой торговой сессии, не создавая свечей в перерывах, выходные и праздники.
3. Для дневных свечей использовать подтверждённые торговые даты конкретного рынка, а не правило будних дней.
4. Проверять полноту календарного ответа на весь запрошенный диапазон. Пустой или частичный ответ не означает отсутствие торгов.
5. При 401/403, ошибке сети, неполном архиве, неизвестном board или неподтверждённой семантике временных меток возвращать null schedule; CandleGapAnalyzer должен оставить gapCount = null.
6. Не сохранять нулевое количество пропусков как подтверждённое, если календарь не прошёл проверку полноты.

## Room и безопасность

Использовать существующие поля history_coverage.gapCount и gapsJson. Миграция Room не требуется. Не менять исходные OHLCV, не подменять пропуски нулями. Компоненты остаются read-only; брокерские заявки не отправляются.

## Следующие этапы

1. Найти и подтвердить бесплатный независимый источник исторических торговых дат для дневных баров; проверить фактический доступ и полноту по контрольным инструментам и годам.
2. Если такого источника нет, сохранить UNKNOWN, а не вводить эвристический календарь.
3. Для внутридневных баров отдельно вернуться к официальному session schedule, когда появится доступ без ALGOPACK либо иной документированный источник.
4. После подтверждения источника реализовать адаптер ExpectedCandleSchedule, покрыть его тестами на реальные ответы и подключить к сохранению history_coverage.
