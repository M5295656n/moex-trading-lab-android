# Календарь MOEX и оценка актуальности данных

## Что подтверждено документацией

MOEX описывает отдельные машиночитаемые календарные ресурсы:

- Фондовый рынок: `/iss/calendars/stock.json` — таблица `off_days`; `/iss/calendars/stock/session.json` — `session_schedule`.
- Срочный рынок: `/iss/calendars/futures.json` — `off_days`; `/iss/calendars/futures/session.json` — `session_schedule`.
- В календаре фондового рынка расписание задаётся по дате, board, SECID, типу периода и времени начала/окончания. Пустой SECID может обозначать общее расписание.
- Для срочного рынка расписание содержит дату, SECID, board, тип и абсолютные даты/время начала и окончания сессии.
- Признак торгового дня может быть 0, 1 или null; null означает отсутствие данных, а не выходной.
- В описании фондового календаря перечислены утренняя, основная, вечерняя и дополнительная сессии. Для фьючерсов отдельно присутствуют клиринговые и расчётные сессии.

Документация: https://moexalgo.github.io/docs/description/calendar-iss/

## Ограничение источника

Документация календарных методов в настоящее время публикует примеры на домене `apim.moex.com`. Текущий клиент приложения обращается к публичному `iss.moex.com` и не имеет механизма API-ключа ALGOPACK. Поэтому нельзя считать доступность календарных методов через текущий публичный endpoint подтверждённой и нельзя незаметно переключать сетевой клиент на API, требующий ключ.

До отдельной проверки HTTP-доступа и условий доступа календарный адаптер остаётся не подключённым к сетевому синхронизатору. В Room сохраняется UNKNOWN, если проверенный календарь недоступен.

## Реализовано в этом изменении

- Добавлен `MarketDataFreshnessEvaluator`, который получает ожидаемые начала свечей от календарного слоя.
- Статусы: FRESH, STALE, MARKET_CLOSED, WAITING_FOR_CANDLE_CLOSE, UNKNOWN.
- Формирующаяся свеча не считается просроченной до истечения её интервала.
- При неизвестном или пустом расписании возвращается UNKNOWN.
- Оценка не использует фиксированный порог «N минут с последней свечи».
- Добавлены unit-тесты для неизвестного календаря, закрытого рынка/ожидания сессии, свежей и устаревшей серии, а также незавершённой свечи.

## Что ещё нельзя считать готовым

1. Нет production HTTP-адаптера календаря.
2. Нет доказанного соответствия типов периодов календаря и свечей ISS для каждого board.
3. Не реализовано построение ожидаемых свечей с учётом аукционов, специальных режимов, торговых перерывов и ночных/выходных сессий.
4. Не подключена запись рассчитанных статусов в `history_coverage`.
5. Текущий формат evaluator ожидает timestamp `yyyy-MM-dd HH:mm:ss`. Перед интеграцией нужно нормализовать дневные свечи и проверить реальные ответы календаря на каждом рынке.

Следующий шаг после проверки доступности календарных методов — написать отдельные stock/futures адаптеры, тесты на реальные ответы ISS и только затем подключить расчёт gaps/freshness к сохранению покрытия истории. Индексы требуют отдельной проверки календарного соответствия; календарь фондового рынка нельзя автоматически считать подтверждённым для каждого индекса.
