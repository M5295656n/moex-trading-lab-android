# Календарно-осведомлённая проверка свечей

## Принцип

Проверка пропусков строится не по постоянному шагу между соседними свечами, а по ожидаемым моментам начала свечей, сформированным из торгового расписания.

- Для внутридневных интервалов ожидаемые свечи формируются отдельно внутри каждой сессии.
- Граница закрытия сессии не считается началом свечи.
- Перерыв между сессиями не порождает ожидаемые свечи.
- Для дневного интервала используются только явно переданные торговые даты.
- Выходные и праздники не вычисляются по календарю понедельник–пятница.
- Если календарь не подтверждён как полный для запрошенного периода, результат имеет статус UNKNOWN и список пропусков остаётся пустым.

## Реализация

CalendarAwareCandleGapAnalyzer — чистый компонент без сетевых и Room-зависимостей. Он принимает уже проверенные сессии/торговые даты и фактические timestamp свечей, возвращает ожидаемое количество, число фактических свечей, пропущенные и неожиданные timestamp.

Статусы:
- COMPLETE — сравнение выполнено по полному календарному входу.
- UNKNOWN — полнота календаря не подтверждена; вывод о пропусках не делается.
- INVALID_INPUT — некорректный интервал или границы сессии.

## Важные ограничения

1. Календарь движка MOEX не является расписанием конкретного инструмента и не должен напрямую порождать свечи.
2. Данные off_days и session_schedule должны быть проверены на фактическую доступность, полноту диапазона, рынок, BOARDID и SECID до передачи в анализатор.
3. Нельзя считать пустой ответ календаря подтверждением отсутствия торговых сессий.
4. Для фьючерсов необходимо сохранить точные временные метки сессий; если API не даёт достаточной детализации, статус должен быть UNKNOWN.
5. Анализатор сравнивает начало свечи. Правила привязки timestamp и возможные частичные свечи должны соответствовать фактической семантике MOEX ISS для каждого интервала.

## Следующий этап интеграции

Подключить анализатор к существующему процессу проверки history_coverage, обеспечить загрузку календаря с привязкой к инструменту/доске и диапазону, сохранить gapCount/gapsJson только при статусе COMPLETE. До завершения этой интеграции существующее значение gapCount = NULL должно сохраняться.
