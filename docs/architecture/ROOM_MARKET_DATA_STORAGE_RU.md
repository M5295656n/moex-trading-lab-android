# Room: локальное хранение рыночных данных

## Схема v2

Существующая таблица `instruments` и DAO сохранены без изменений. Миграция `1 → 2` добавляет:

- `market_instruments` — канонический инструмент. Идентификатор включает рынок, режим торгов и SECID; это предотвращает коллизии одинаковых SECID на разных рынках/режимах.
- `candles` — OHLCV с составным ключом `instrumentId + intervalMinutes + begin`. Отсутствующие значения остаются SQL NULL.
- `history_coverage` — параметры запрошенного диапазона, источник, endpoint, время получения, число страниц, размер страницы, статус пагинации, пропущенные строки, отдельные поля для обнаруженных временных разрывов и актуальности.

## Семантика полноты

`paginationStatus` копирует статус загрузчика ISS: `COMPLETE`, `PAGE_LIMIT_REACHED` или `PAGINATION_STALLED`. `COMPLETE` означает только достижение конца ответа ISS по правилу короткой страницы. Это не доказательство непрерывности торгового ряда. Поля `gapCount` и `gapsJson` остаются NULL, пока отдельный валидатор интервалов не проверит пропуски. `freshnessStatus` также задаётся вызывающим слоем после отдельной проверки актуальности.

## Запись

`MarketDataStorage` преобразует результаты сетевого слоя в Room entities. Каталоги сохраняются пакетным upsert. Свечи и запись покрытия сохраняются одной транзакцией. Внешний слой обязан сначала сохранить инструмент, иначе ограничение внешнего ключа отклонит запись свечей.

## Совместимость

Миграция аддитивная: таблица v1 не удаляется и не преобразуется с потерей данных. Destructive migration не используется. Инструментальная проверка миграции создаёт базу v1 с записью SBER, открывает её через Room v2 и проверяет сохранность записи и доступность новой таблицы.
