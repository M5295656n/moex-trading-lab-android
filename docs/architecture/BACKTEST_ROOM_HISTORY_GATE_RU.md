# Подключение Room-истории к бэктестингу

## Что добавлено

- Read-only репозиторий `BacktestHistoryRepository` выбирает инструмент, свечи и запись покрытия истории из существующих таблиц Room.
- `BacktestRunner` передаёт данные в `BreakoutBacktestEngine` только после успешного результата `BacktestHistorySource`; при отказе проверки симулятор не запускается.
- `BacktestHistoryGate` проверяет, что одна запись покрытия целиком охватывает запрошенный диапазон.
- Для запуска требуются источник MOEX ISS, завершённая пагинация, отсутствие пропущенных строк и явно подтверждённое отсутствие пропусков свечей (`gapCount = 0`, `gapsJson = []`).
- Проверяются принадлежность свечей инструменту/интервалу, источник, хронология, формат времени и OHLC.
- Отсутствующие OHLC не заменяются нулями; при неизвестном качестве истории запуск отклоняется.
- В результате сохраняются метаданные источника, времени загрузки, свежести и идентификатор покрытия.

## Безопасное поведение

Текущая синхронизация MOEX ISS записывает `gapCount = null` и `freshnessStatus = UNKNOWN`, пока отдельная проверка непрерывности не выполнена. Поэтому свежезагруженная история пока закономерно не проходит gate. Это намеренно: полнота пагинации не доказывает отсутствие пропусков между торговыми свечами.

## Ограничения

- Требуется единая запись покрытия на весь диапазон; автоматическое объединение нескольких частичных загрузок пока не реализовано.
- Для проверки пропусков нужен корректный ожидаемый график свечей по рынку, board и таймфрейму. Текущий engine-level календарь MOEX не является календарём торгов конкретного инструмента и не используется как его замена.
- Gate не запускает симулятор и не меняет Room-схему. Он только подготавливает и проверяет входные данные для существующего движка.
- Фьючерсы не допускаются к полноценному бэктесту до внедрения спецификаций контрактов и риск-параметров.


## Проверка качества истории

- `MoexDailyHistoryCoverageVerifier` сверяет дневные свечи акций с расписанием MOEX по SECID и BOARDID. Несколько сессионных периодов одного дня сводятся к одной дневной свече.
- Проверка сохраняет пропуски и неожиданные даты в существующую запись покрытия; статус свежести не подменяется результатом проверки непрерывности.
- Неизвестное расписание, пустой ответ, другой рынок или неподдерживаемый интервал остаются UNKNOWN. Это не считается нулём пропусков.

## Ограничения

- Пока поддерживается только дневная история рынка акций (SHARES). Индексы, фьючерсы и внутридневные интервалы 1/10/60 минут остаются непроверенными.
- Расписание MOEX для акций содержит периоды торгов по режиму и исключает дискретные аукционы. Для дневных свечей периоды агрегируются по торговой дате.
- Для intraday нужно отдельно учесть типы сессий, клиринговые паузы и границы баров; простое прибавление N минут к началу сессии не используется.
