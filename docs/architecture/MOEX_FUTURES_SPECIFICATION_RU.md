# Спецификация фьючерсов MOEX ISS

## Два уровня источников

### 1. Общедоступный каталог FORTS

Базовые сведения о контрактах загружаются через общедоступный метод:

- `/iss/engines/futures/markets/forts/securities`

Среди документированных полей каталога:
- `SECID`, `SHORTNAME`, `SECNAME`;
- `MINSTEP` — минимальный шаг цены;
- `DECIMALS` — число десятичных знаков;
- `PREVSETTLEPRICE` — расчётная цена предыдущего дня;
- `LASTTRADEDATE` — последний торговый день;
- `LASTDELDATE` — дата исполнения.

Реализация `MoexPublicFuturesCatalogRepository` читает только эти поля, проверяет полноту пагинации и однозначность SECID. Значения, отсутствующие в ответе, остаются null.

**Этот каталог не предоставляет достаточных подтверждённых данных для денежного расчёта риска фьючерса.** В частности, из `MINSTEP` нельзя вывести денежную стоимость шага, а из предыдущей расчётной цены нельзя вывести гарантийное обеспечение. Публичная метаинформация пригодна для отображения и проверки контракта, но сама по себе не разрешает расчёт размера позиции.

### 2. Расширенные справочные данные Reference Data

Расширенные торговые и риск-параметры запрашиваются тремя методами:

- `/iss/referencedata/engines/futures/markets/forts/securities`
- `/iss/referencedata/engines/futures/markets/forts/params`
- `/iss/referencedata/engines/futures/markets/forts/risks`

Эти методы относятся к продукту MOEX «Справочные данные». **Нельзя считать, что они доступны каждому пользователю без подписки или специальных прав.** При HTTP-ошибке доступа приложение не должно обходить ограничения, подставлять значения или заявлять, что расширенная спецификация получена из бесплатного источника.

Официальные материалы:
- https://www.moex.com/files/4yvyp2s15qnhjw69mpeezye5nd
- https://www.moex.com/en/referencedata
- https://www.moex.com/n94033

## Сопоставление расширенных полей

| Назначение | Источник | Поля |
|---|---|---|
| Идентификатор контракта | securities | TICKER / SHORT_TICKER |
| Идентификатор контракта | params | CONTRACT |
| Идентификатор контракта | risks | TICKER |
| Шаг цены | params | TICK |
| Стоимость шага, ₽ | params | TICK_PRICE |
| Шаг цены (контроль) | securities | MIN_STEP |
| Стоимость шага, ₽ (контроль) | securities | MIN_STEP_PRICE |
| ГО, ₽ | params | DEPOSIT |
| ГО, ₽ (контроль) | risks | MARGIN |
| Последний день торгов | securities | END_DATE |
| Дата исполнения | securities / risks | EXP_DATE |
| Торговая дата данных | все блоки | REFERENCE_DATE |
| Время формирования | все блоки | DOC_DATE |
| Дата вступления параметров в силу | все блоки | EFFECTIVE_DATE |

## Правила валидации расширенной спецификации

- Все три таблицы должны быть загружены полностью. Достижение лимита страниц не считается полной загрузкой.
- Каждая таблица должна содержать однозначную запись по SECID. Отсутствующая или неоднозначная связь блокирует расчёт.
- В каждой используемой записи обязательны `REFERENCE_DATE`, `DOC_DATE` и `EFFECTIVE_DATE`. `REFERENCE_DATE` должна совпадать с запрошенной торговой датой. Нельзя заменять время формирования временем получения ответа.
- Будущая `EFFECTIVE_DATE` блокирует использование записи.
- Если одновременно доступны `TICK` и `MIN_STEP`, их значения должны совпадать. Аналогично для `TICK_PRICE` и `MIN_STEP_PRICE`.
- ГО берётся как максимальное положительное значение из `DEPOSIT` и `MARGIN`, если оба присутствуют. Это консервативно ограничивает количество контрактов по капиталу.
- Для границы срока жизни контракта используется самая ранняя доступная дата из `END_DATE` и `EXP_DATE`, чтобы не допустить расчёт после последнего дня торгов.
- Время формирования спецификации для калькулятора — самое раннее из DOC_DATE всех трёх таблиц; свежесть составной спецификации определяется по самому старому компоненту.
- Комиссия брокера за контракт не выводится из биржевого поля `FEE`: сбор биржи/клиринга не тождественен тарифу брокера. Комиссия брокера остаётся отдельным обязательным вводом.

## Текущее состояние реализации

- `MoexPublicFuturesCatalogRepository` добавлен как отдельный read-only загрузчик общедоступных метаданных. Добавлены тесты маппинга, отсутствующих полей, конфликтующих дубликатов, отсутствующего контракта и неполной пагинации.
- `PublicFuturesMetadataCard` подключена к экрану графика для выбранного фьючерса: отображает MINSTEP, DECIMALS, PREVSETTLEPRICE, LASTTRADEDATE, LASTDELDATE, источник и время получения. Есть ручное обновление и повторная загрузка при ошибке.
- `MoexFuturesSpecificationRepository` пока использует три расширенных Reference Data метода. При ошибке доступа карточка должна оставаться заблокированной для расчёта.
- Реальные ответы ISS и успешная Android-сборка ещё не подтверждены. Unit-тесты дополнены проверкой отрицательной конечной расчётной цены, но не выполнены: GitHub Actions ранее не запускал job из-за проблемы Billing.
- Данные не сохраняются в Room на этом этапе; схема базы и миграции не меняются.
- Автоматическая отправка брокерских заявок отсутствует.
